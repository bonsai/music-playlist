# Radiooooo → Last.fm スキーム簡素化提案書

## 現状の問題

現在の UI は「1 ページにすべて詰め込んでいる」状態です。

| 箇所 | 入っているもの |
| --- | --- |
| ポップアップ | 認証、現在曲、scrobble バー、キュー、JSONL 出力、bridge 状態、設定ボタン |
| 設定ページ | 認証、動作、再生履歴、診断、**イベントログ**、プレイリスト |

ユーザが「今、曲が送られているか？」を知ろうとして
ポップアップを開いても、設定入力欄やログが混在しており、
目的の情報が 1 クリックで見えません。特に「設定」と「ログ表示」が
同一画面に共存しているため、以下の摩擦があります。

- ポップアップを開く → ログを探す → ログを閉じる → 設定を探す
- ポップアップが情報過多で、小さめの画面ではスクロール必須
- 設定入力を間違えるとログがごちゃ混ざり、何が何だか分からない

## 方針

**ポップアップを「3 タブ」に切り分け、目的ごとに画面を分ける。**

| タブ | 役割 | 入るもの |
| --- | --- | --- |
| **再生中** | 第 1 目的：今何が起こっているか | 現在曲、scrobble バー、キュー、再送 |
| **設定** | 第 2 目的：認証・動作 | API key/secret、トグル、JSONL 出力 |
| **ログ** | 第 3 目的：追跡・診断 | イベントログのみ（下 50 件）、コピー/消去 |

**Options ページは「深さ」の役割を残す。**
設定ページの「再生履歴（JSONL）」と「拡張診断」はポップアップより奥行きが必要な
機能なので残し、代わりに「認証」「動作」「詳細」だけを簡素化する。

## 新ポップアップ構成案

```
┌──────────────────────────────────────┐
│ [ 再生中 ] [ 設定 ] [ ログ ] ← タブ   │
├──────────────────────────────────────┤
│ Radiooooo → Last.fm                    │
│ ┌──────────────────────────────────┐  │
│ │ 未認証    │ 設定 │ 再送          │  │
│ └──────────────────────────────────┘  │
│ ┌──────────────────────────────────┐  │
│ │ Way Dynamic — Not A Fan            │  │
│ │ album: Not A Fan · AUS · 2022     │  │
│ │ ████████░░░░░░░░░░░░ 72%          │  │
│ │ ▶ 再生中 · 108s / 150s · あと 42s │  │
│ └──────────────────────────────────┘  │
│ ┌──────────────────────────────────┐  │
│ │ 未送信キュー    0                 │  │
│ └──────────────────────────────────┘  │
└──────────────────────────────────────┘
```

タブ切り替えはローカルな表示のみで、状態は常に service worker の
`chrome.storage.local` から再取得します。

### 設定タブ

- API key / Shared secret（`type="password"` で平文表示を防止）
- Now Playing / Scrobble チェックボックス
- JSONL 出力ボタン（現在曲 + キューを 1 行）

### ログタブ

- イベントログの下 50 件（`good`/`bad` で色分け）
- クリップボードコピー / 消去
- 自動更新はオフ（手動「更新」ボタン）

## 影響範囲

| 変更 | 内容 |
| --- | --- |
| `popup.html` | 3 タブ構造に書き換え |
| `popup.ts` | 表示/設定/ログ用の 3 関数＋タブ遷移ロジック |
| `styles.css` | タブ用スタイル（`.tab`, `.tab-content`, `.hide`） |
| Options | 不要なら「認証」「動作」「履歴」だけ残して簡素化（次工程） |

## 非変更（維持）

- service worker の処理（メッセージ、queue、scrobble）
- shared モジュール（normalize, scrobble, lastfm, jsonl）
- content scripts（bridge, detector, token-sniffer）
- 全ユニットテスト（20 件）

## 実装の手順

1. `popup.html` を 3 タブ構造に置き換え
2. `popup.ts` に `renderNowPlaying` / `renderSettings` / `renderLogs` を追加
3. タブ切り替えイベントを実装（CSS `.tab.active` / `.tab-content.active`）
4. `types.ts` の `StateSnapshot` に `log: LogEntry[]` が含まれることを確認
5. `npm run check` で型チェック＋テスト、`npm run smoke` で動作確認

## 検証シナリオ

1. ポップアップ開く → 再生中タブが見える
2. 「設定」タブ → API key 入力欄が見え、`type="password"`
3. 「ログ」タブ → イベントログのみが並び、コピーボタンが効く
4. 曲検出 → 再生中タブのバーが動く（タブに関係なく）
5. Last.fm 認証 → 設定タブ保存で反映、再送で送信
